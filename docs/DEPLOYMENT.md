# Deployment (Render)

> **Live address:** https://driveroncall.onrender.com (service name `driveroncall`; Render fixes a service's web address when it is created, so the earlier long address `doc-driver-on-call-8sl8.onrender.com` was replaced by a new service).
>
> **Current setup (2026-11-17): the FREE instance.** It has no persistent disk, so all data (users, bookings, uploaded documents) is erased whenever the service restarts, redeploys or wakes from sleep, and the first visit after a sleep is slow. It is good for a look-around, not for real users. To keep data, switch `render.yaml` to the paid setup below: `plan: starter`, add the disk, and set `DB_DIR=/var/data/db` and `UPLOAD_DIR=/var/data/uploads`. Everything below describes that paid setup.

Last updated: 2026-11-17

The whole app (API and web pages) runs as one Node web service on [Render](https://render.com). `render.yaml` in the project root describes it, so Render can create everything from the GitHub repository.

## What the blueprint sets up

| Setting | Value | Why |
| --- | --- | --- |
| Instance | `starter` (paid) in Singapore | A persistent disk is only available on paid instances. Singapore is the nearest region to India |
| Disk | 1 GB at `/var/data` | Holds the SQLite database (`DB_DIR`) and uploaded documents (`UPLOAD_DIR`). Without it, every restart or redeploy would erase them |
| Build | install all three packages, then build the web app | |
| Start | `npm start` | Serves the API and the built web app on one address |
| Health check | `/api/health` | Render restarts the service if the database stops answering |
| `TZ=Asia/Kolkata` | | Working hours are evaluated in the server's time zone |
| `NODE_VERSION=22.15.0` | | The app uses Node's built-in SQLite, which needs Node 22.5 or newer |
| `DEMO_MODE=false` | | Removes the demo logins and the "add demo drivers" button |
| `JWT_SECRET` | generated by Render | Signs login tokens |

Secret or personal values are typed into Render's dashboard, never committed: `GOOGLE_CLIENT_ID`, `ADMIN_EMAILS`, `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_VERIFY_SERVICE_SID`.

## Steps

1. Sign in to Render (signing in with GitHub is simplest) and allow it to read the repository `driver-on-call`.
2. New → Blueprint → choose the repository. Render reads `render.yaml`. It shows the monthly price of the instance and disk before you confirm; check it there.
3. Fill in the five values above when asked. `ADMIN_EMAILS` is the Google email that should be able to approve drivers.
4. After the first deploy finishes, note the address (for example `https://doc-driver-on-call.onrender.com`).
5. In Google Cloud (project Driver-On-Call, dev account), edit the OAuth client: add the address under *Authorised JavaScript origins* and `<address>/login` under *Authorised redirect URIs*. Changes can take a few minutes.
6. Open the address, sign in with Google, and open the Admin link.

## Limits to know about

- **Phone verification:** the Twilio trial can only text up to 5 numbers verified in the Twilio console. Other people cannot get a code, so they cannot book or apply. Upgrade Twilio, or switch provider, before inviting real users.
- **Google sign-in:** while the consent screen is in "Testing", only listed test users can sign in. Press "Publish app" to open it to everyone.
- **One server only:** SQLite is a single file on one disk, so run exactly one instance. Moving to PostgreSQL is the step that allows more.
- **Backups:** Render disks can be snapshotted, but plan an off-site copy of `/var/data/db` before real data matters.
- **Documents:** identity documents are stored unencrypted on the disk.
- **Deploys:** pushing to `main` redeploys automatically. A deploy restarts the service for a short while.
